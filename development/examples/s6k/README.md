# S6k pilot fixture

This feature payload is derived from Laura K. Reed, *Model: Gene model for the
ortholog of S6k in Drosophila ananassae*, CaltechDATA v1.0, CC BY 4.0.
The publication and the deposit have separate identifiers.

- [Model deposit](https://doi.org/10.22002/e86gh-a7p16)
- [Deposit rights metadata](https://api.datacite.org/dois/10.22002/e86gh-a7p16)
- [Article](https://pmc.ncbi.nlm.nih.gov/articles/PMC12464738/)

From this directory, regenerate the fixture from the original deposit ZIP.

```sh
python3 convert.py /path/to/DanaCAF1_S6k.zip > /tmp/DanaCAF1_S6k.gff3
cmp DanaCAF1_S6k.gff3 /tmp/DanaCAF1_S6k.gff3
gff3-validate --no-header DanaCAF1_S6k.gff3
```

The converter checks the archive SHA-256 before reading the annotation member.
It replaces the browser track line with the GFF3 version directive, converts
the source IDs to `ID` and `Parent` relationships, and creates one gene and two
mRNA features with bounds covering their children. It keeps every deposited
CDS, exon and stop codon row, including its coordinates, strand and phase.
The separately annotated stop codons remain separate, immediately beyond the
last deposited exons. This preserves the source annotation for review without
extending exons or merging stops into CDS rows.

## Reference and profile validation

Download the versioned [NCBI assembly FASTA](https://ftp.ncbi.nlm.nih.gov/genomes/all/GCA/000/005/115/GCA_000005115.1_dana_caf1/GCA_000005115.1_dana_caf1_genomic.fna.gz).
With Python 3.11 or newer and gff3-validator installed, run:

```sh
python3 verify_reference.py /path/to/DanaCAF1_S6k.zip /path/to/GCA_000005115.1_dana_caf1_genomic.fna.gz
```

The script pins the compressed assembly by SHA-256. It computes the
[GA4GH SeqCol v1.0.0](https://ga4gh.github.io/refget/seqcols/) level-0 digest
using the first token of each FASTA defline, uppercase sequences, and the
original order of all 13,749 records. The NCBI sequence record identifies
`CH902618.1` as `scaffold_13337`.

| Check | Result |
| --- | --- |
| Reproducibility | The ZIP matched its recorded SHA-256 and the plain GFF3 regenerated byte for byte. Removing the header lines from the profile fixture yields the same payload. |
| Reference and companion files | PA and PB each match their deposited 1,467-nt transcript and 489-aa peptide. The separate stop interval is `TAA` in both cases. |
| GFF3 features | gff3-validator 0.1.0 at `c753f45` reported zero errors and warnings without a genome. With `CH902618.1` supplied under the source scaffold name, it reported zero errors and two BIO-007 warnings. Each CDS ends with `GTC`; the following `TAA` is in a separate source feature. |
| Header schema | The parsed header passed Draft 2020-12 validation against [FHGFF3 1.1 from v0.5.0](https://github.com/FAIR-bioHeaders/FAIR-bioHeaders-Specification/blob/v0.5.0/fhgff3.json) with format checks. The local toolkit 0.8.2 rejected the v0.5.0 schema URI as unsupported. |
| Exact-byte checksum | SHA-512/256 over all bytes except the root checksum line matched the recorded padded Base64 value. OpenSSL independently reproduced it. |

To reproduce the profile checks, run from this directory:

```sh
awk '!/^#~/' DanaCAF1_S6k.fhgff3.gff3 | cmp DanaCAF1_S6k.gff3 -
awk '!/^#~checksum:/' DanaCAF1_S6k.fhgff3.gff3 |
  openssl dgst -sha512-256 -binary | openssl base64 -A
```

For schema validation, extract the contiguous leading `#~` lines, remove
their two-byte prefixes, and parse them as YAML. Validate the result against the
linked schema with a Draft 2020-12 validator and URI/date format checks.

The [profile fixture](DanaCAF1_S6k.fhgff3.gff3) uses the released FHGFF3
identity and an experimental `x-fhgm-contribution-scope` field. Its article DOI
and source deposit DOI have separate roles. The extension demonstrates that a
single-locus contribution can fit the base schema. A revised-model fixture and
curator review are needed to test how to represent evidence, contributor roles,
and supersession before deciding on FHGM type identity.
