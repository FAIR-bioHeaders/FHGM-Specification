# FHGM development plan

Status: draft validation, 2026-11-10. Refs
[family issue #204](https://github.com/FAIR-bioHeaders/FAIR-bioHeaders-Specification/issues/204).
This directory contains the proposal and its review implementation.

## Setup provenance

FHGM was created as a fork of FAIR-bioHeaders/FHGFF3. This setup starts at
`1bfccedbe444e5a9d9c39ae3e7d1b35e43df77e0`, cloned on 2026-11-05.
The inherited header retains its separately recorded shared-source pin; no
baseline files are relabeled or regenerated by this setup.

## Work sequence

- [ ] Consult gene-model authors/curators about submission and reuse requirements.
- [ ] Select new-model and revised-model deposits; cover multiple isoforms and a noncoding case where available.
- [ ] Complete [the comparison](FHGFF3-COMPARISON.md), recording an explicit FHGFF3 base revision and contract version.
- [ ] Decide subtype versus sibling contract, scope/cardinality, header identity, and feature constraints with David and Adam.
- [ ] Draft requiredness, field semantics, roles, evidence, revision/split/merge relationships and mappings; identify schema additions explicitly.
- [ ] Establish a separate draft model, reproducible generation and validation commands, plus minimal/rich and rejected conformance cases.
- [ ] Review serialization/type dispatch, compatibility, INSDC coverage and shared publication integration.
- [ ] Coordinate toolkit and website support in linked work after the draft is reviewed.

## Completion criteria for the first design pass

Each proposed requirement has an example or curator rationale, a location (header
or GFF3 feature layer), a comparison with existing FHGFF3 support, and an explicit
validation boundary. Record unknowns rather than filling them with plausible
metadata. No decision is implied by checking a repository-setup task complete.

## Working paths

Use [examples/](examples/README.md) for source-selection and provenance records.
Keep actual retrieved payloads out until reuse terms are inspected. The
[draft model and validator](model/README.md) live separately from the
immutable reference baseline.
